# Solution Comparison

| Solution | Deployment Target | Baseline Monthly Compute Cost* | Cold/Warm Start Strategy | Automation Complexity | When to Prefer |
| --- | --- | --- | --- | --- | --- |
| Lightsail Container | AWS Lightsail Container Service (Micro) | $10 flat when running; scale nodes to zero for $0 compute.【F:plans/aws-lightsail-container.md†L32-L38】 | Container warm within ~2 minutes; schedule stop to save cost.【F:plans/aws-lightsail-container.md†L22-L31】 | Simple GitHub Action with single CLI command.【F:plans/aws-lightsail-container.md†L6-L14】 | When bundled bandwidth and predictable pricing matter more than advanced routing. |
| Lightsail Instance | AWS Lightsail Linux VM ($5 tier) | $5 flat while powered on; stop instance to pause compute charges.【F:plans/aws-lightsail-instance.md†L31-L38】 | Prebaked snapshot boots with Docker ready; use stop/start automation overnight.【F:plans/aws-lightsail-instance.md†L15-L29】 | Moderate—requires Terraform/Packer but reuses Docker Compose directly.【F:plans/aws-lightsail-instance.md†L6-L23】 | When you need full Compose compatibility or sidecar containers. |
| App Runner | AWS App Runner | $0.007/GB-hour provisioned + $0.064/vCPU-hour when active.【F:plans/aws-app-runner.md†L28-L36】 | Keep 1 provisioned instance for fast resume; pause service to avoid active costs.【F:plans/aws-app-runner.md†L18-L27】 | Moderate—requires ECR + App Runner CLI orchestration.【F:plans/aws-app-runner.md†L6-L16】 | When managed TLS and zero infrastructure management outweigh higher consumption pricing. |
| Cloud Run | Google Cloud Run | $0.000024/vCPU-s + $0.0000025/GiB-s; $0.40 per million requests.【F:plans/gcp-cloud-run.md†L31-L38】 | Scale-to-zero with Scheduler to reach near $0 idle cost.【F:plans/gcp-cloud-run.md†L19-L27】 | Low—`gcloud run deploy` with Workload Identity Federation.【F:plans/gcp-cloud-run.md†L6-L15】 | When rapid deployments and minimal ops are priorities, and egress rates are acceptable. |
| Multi-Cloud Active/Standby | Cloud Run (active) + Lightsail Container (standby) | Active billing on Cloud Run rates plus standby $10/mo when powered; scale both to zero when idle.【F:plans/multi-cloud-active-standby.md†L29-L38】 | Cloud Run handles primary traffic; Lightsail nodes kept at zero until failover drill.【F:plans/multi-cloud-active-standby.md†L17-L28】 | High—requires dual-provider pipelines and secret sync.【F:plans/multi-cloud-active-standby.md†L6-L24】 | When resiliency across providers is critical or you need blue/green experiments. |

\*Costs shown for us-east-1/us-central1 public pricing at the time of writing; exclude storage, data transfer, and ancillary services.

## Additional Observations
- All solutions rely on pre-rendered configuration artifacts and avoid re-running Ansible at deploy time, meeting the sub-two-minute startup goal.【F:plans/aws-lightsail-container.md†L6-L14】【F:plans/aws-lightsail-instance.md†L6-L14】【F:plans/aws-app-runner.md†L6-L13】【F:plans/gcp-cloud-run.md†L6-L13】【F:plans/multi-cloud-active-standby.md†L6-L13】
- GitHub Actions with OIDC authentication is the common trigger, reducing credential sprawl and enabling one-line workflow dispatches across providers.【F:plans/aws-lightsail-container.md†L10-L14】【F:plans/aws-lightsail-instance.md†L19-L23】【F:plans/aws-app-runner.md†L10-L14】【F:plans/gcp-cloud-run.md†L9-L13】【F:plans/multi-cloud-active-standby.md†L8-L13】
- Scheduling controls (EventBridge, Cloud Scheduler) are available in every plan to destroy or pause compute nightly for cost savings.【F:plans/aws-lightsail-container.md†L22-L31】【F:plans/aws-lightsail-instance.md†L23-L29】【F:plans/aws-app-runner.md†L18-L27】【F:plans/gcp-cloud-run.md†L22-L27】【F:plans/multi-cloud-active-standby.md†L24-L28】
